# Agent Rules — Darkest Tico

These rules apply to every agent (Claude Code, Cursor, Codex, a human) working in this repo. The goal: **any agent can stop at any point, and the next one can pick up without asking anyone.**

## 1. Start of session (always, in this order)

1. Read the **top entry** of [docs/HANDOFF.md](docs/HANDOFF.md). It says what the last agent did and the exact next step.
2. Open [docs/12-phase-plan.md](docs/12-phase-plan.md) and find the current phase.
3. Pick a task:
   - If the user named one, do that.
   - Else continue any task marked `in-progress` from the last handoff.
   - Else take the first `todo` task in the current phase whose dependencies are all `done`.
4. **Claim it**: set the task's status to `in-progress (<agent>, <branch>, <YYYY-MM-DD>)` in the plan.
5. Read only the design docs the task lists under **Spec**. Do not re-derive design from scratch; the docs in `docs/01`–`docs/09` are the source of truth.

## 2. While working

- Work on **one task at a time**. If you find more work, add it to the plan as a new `todo` task (next free ID in that phase) instead of doing it unasked.
- Stay inside the task's scope and file list. Touching other files is fine when needed. Say so in the handoff.
- Data goes in `data/*.json`, not hard-coded in scripts. Balance numbers (hit band, crits, death roll, stress, hub prices, limits) go in `data/balance.json` and are read with `Balance.num("section.key")` (`scripts/domain/balance.gd`). New keys must be added to `BALANCE_KEYS` in `tools/validate_data.py`, which also rejects numeric consts and numeric `.get(…, N)` fallbacks in `scripts/domain/` (mark real structural numbers `# structural`). Rules go in `scripts/domain/` (pure, no nodes). UI goes in `scripts/<screen>/`.
- If the design is unclear or contradicts the code, write the question under **Decisions needed** in your handoff entry. Then pick the smallest reasonable default and keep going.
- Never delete a task. If it is no longer wanted, set it to `cut — <reason>`.

## 3. End of session — the handoff (mandatory)

Do this before you stop for **any** reason: task finished, context running out, blocked, or the user ends the session.

1. **Verify**
   - `python3 tools/validate_data.py` must exit 0.
   - If Godot is installed (see [.cursor/rules/godot-runtime.mdc](.cursor/rules/godot-runtime.mdc); cloud agents may download the official 4.7.2 Linux build into their scratchpad, owner-approved 2026-11-07):
     - `godot --headless --path . --import` (first run / new files; generates `.uid` files — commit them)
     - `godot --headless --path . -s tests/run_tests.gd` (P1-01) runs the smoke test (3 full expeditions) and every `tests/test_*.gd`, each in its own process, and exits 1 if any fails or prints `SCRIPT ERROR`; about 2–3 minutes. `-- --only test_hub,test_ui` / `-- --skip smoke_expedition` / `-- --verbose`. New `tests/test_*.gd` files join automatically.
   - If you could not verify something (for example, no Godot in a cloud container), **say so explicitly** in the handoff.
2. **Update the plan**: set your task's status to `done`, `review` (works but needs a human check), `blocked — <why>`, or leave it `in-progress` with a note. Tick any finished acceptance checkboxes.
3. **Write the handoff entry**: add it at the **top** of [docs/HANDOFF.md](docs/HANDOFF.md) using the template there. The **Next step** line must be specific enough that a fresh agent can act on it without reading the conversation.
4. **Commit and push**: one commit (or more) whose message starts with the task ID, for example `P1-02: multi-enemy squads`. Never leave work uncommitted or unpushed. The container or machine may be gone next time.

## 4. Content rules (owner decisions — `tools/validate_data.py` enforces them)

- **Recruits** (owner 2026-11-15, as in Darkest Dungeon): hiring at the Terminal de Buses is free; only the beds (`limits.roster_cap`) limit it. The one priced hero is the veteran a town event offers (`hire_veteran`).
- **Heroes:** every class has at least one skill that helps **one ally or the whole party** (`target: ally | party`). Every class has **its own basic attack** as its first skill (kind `attack`, fitting the weapon its sprite holds), and no skill is shared by two classes (owner 2026-11-11). Skills use doc 03 names. **Skills to learn** (P3-17, owner 2026-11-23): every class has 7 skills, 4 known at hire (`skill_ids`) and 3 learned once per hero at the Casa Comunal (`extra_skill_ids`, `GameState.learn_skill`); a hero brings 4 of what they know (`hero.skill_ids` is always that loadout, `hero.skill_known` all of them), swapped free in town (`GameState.set_skill_slot`), never on an expedition; the basic attack stays in slot 1. The validator checks 4 + 3 per class and that every skill belongs to exactly one class.
- **Enemies:** every enemy has a **`family`** (espantos, culto, bestias, penados, infernales; P6-03), may be **large** (`size: 2`, two positions) and may have **`phases`** (at a PV %: statuses, protection, mirror images). Exactly **one basic attack** (`basic: true`) plus **1–3 special abilities**. At least one special is **magical** (`type: magical`, goes through Guard) or **inflicts a negative status** (`applies`, any negative id in `data/statuses.json`).
- **Names:** every ability has a **Costa Rican (Tico) name that fits that specific monster or class**, written in Spanish, within the tone rules of doc 08 (e.g. Mandador en pena → *Latigazo*, *Libreta de deudas*; Cadejo → *Aullido de medianoche*).
- **Guard:** halves physical damage until the hero's next turn; magical attacks and `ignores_guard` skills go through it.
- **Shops** (P4-18, owner 2026-11-17; P3-05a, owner 2026-11-20): the **Pulpería** sells only consumables; the **Taller de Herrería y Carretas** sells weapons and armor, only this week's stock (P3-05e, owner 2026-11-22: `taller.stock_weapons` / `stock_armor`, `GameState.taller_stock`, one of each, rerolled every week with the Feria's draw); the **Feria Nocturna** sells accessories, only the few on this week's stall (`data/balance.json` `feria.*`, `GameState.feria_stock`, one of each, rerolled every week, rules in `scripts/domain/feria.gd`). **Cursed trinkets** (P3-05b: `cursed: true` accessories with a strong bonus and a real drawback) come only from the Feria, one on top of the stall at `feria.cursed_chance` a week; never as drops, curio loot or event gifts (the validator checks drops). `GameState.shop_of` says which. Town-event closures are per shop (`pulperia_compra/_venta`, `taller_compra/_venta`, `feria_compra/_venta`).
- **Selling** (owner 2026-11-17): each shop buys back only what it sells, at **half its price** (`data/balance.json` `hub.sell_rate`): consumables at the Pulpería, weapons and armor at the Taller, accessories at the Feria (they don't go back on its stall) (`GameState.sell_item(id, shop)`; `shop` "" = the item's own shop). Equipped items must be unequipped first.
- **Enemy drops** (P5-10, owner 2026-11-19): every enemy lists exactly **3 drops** (`drops`: item + chance) that fit it; when it dies (not when it flees) **one roll** decides whether **one** of them drops, and most kills drop nothing (the three chances add up to at most 0.8). Stronger enemies drop more often and better items (vermin ~15%, ordinary ~20%, the roaming Cadejo ~45%, bosses ~70%); harder difficulties and darker Luz raise the odds (`data/balance.json` `drops.*`). After every won fight a card shows the loot and how each hero came out of it.
- **Building upgrades and Reliquias** (P3-14/16/18/21, owner 2026-11-20): upgrades cost **Reliquias del Abuelo + colones** (Casa Comunal, Iglesia, Cantina, Guardabosques, the Feria Nocturna's *Tamaño de Puestos* / *Cadena de Comerciantes*, P3-05b, and the Taller's *Forja de Machetes* / *Chapería de Armaduras* / *Horno Eficiente*, P3-05d, and *Bodega de Hierros*, which adds weapons and armor to its weekly stock, P3-05e; `data/upgrades.json`, `scripts/domain/building_upgrades.gd`, `GameState.buy_upgrade`). Reliquias are a hacienda counter (not an item) from cleared objectives (per difficulty), elite / roaming kills and a few curios. The Casa Comunal teaches up to **rank 3** until *Maestría de Oficio* raises it (heroes above the cap keep their ranks). EBAIS and Iglesia/Cantina prices scale with the hero's resolve tier (`hub.tier_price_mult`); always read prices through `GameState` (`activity_cost(b, a, hero)`, `heal_cost`, `skill_rank_cost`, `camp_price`), never from the data.
- **Items:** outside combat, each hero can use each item `uses_per_node` times per room (per character, not per team). Using an item in combat spends the hero's turn.
- **Damage outside combat** (owner 2026-11-12): traps and curios use the combat rule (`scripts/domain/hero_damage.gd`): Al Borde, then Golpe de gracia; heroes can die. Hunger and fasting never drop a hero below 1 PV.
- **Luz** (owner 2026-11-12, DD torch): 5 tiers in `data/balance.json` `light.tiers` (doc 01 §4.5). Darker means worse hero accuracy, more enemy damage and crit, more stress, more loot, more surprises and harder traps.
- **Hunger** (owner 2026-11-12): every 6 moves, 1 gallo pinto per living hero; whoever doesn't eat loses 10% PV (never below 1) and gains 10 stress; a camp meal resets the count (doc 01 §4.6). Regions list two recommended `provisions` kits (owner 2026-11-14): `short` for a run straight to the boss and `full` for exploring every room; the hub shows both before leaving.
- **Traps and curios:** data in `data/traps.json` / `data/curios.json` with one outcome vocabulary (`GameState.apply_event_outcome`), checked by the validator. Trap disarm is DD-style: best *trampa* + Luz bonus − difficulty.
- **Elements** (classic RPG set): fuego, hielo, rayo, agua, tierra, viento, sagrado, oscuridad. **Every enemy has elemental affinities** (`elements`: >1 weak, <1 resists, 0 immune) that fit the monster; enemy magic skills carry an `element`.
- **Equipment:** each hero wears **1 weapon, 1 armor, 2 accessories**, all Tico-themed. Bonuses: damage, accuracy, crit, dodge, speed, HP, protection %, stress resistance %; weapons may be typed (`element`), armor/accessories may resist elements or grant ailment immunity. Weapons and armor are sold at the Taller, accessories at the Feria Nocturna. **Weapon and armor ranks** (P3-05d, DD blacksmith): the Taller sharpens a hero's weapon slot and reinforces their armor slot, rank 1–5 (`scripts/domain/gear_ranks.gd`, `data/balance.json` `taller.*`); the rank stays with the hero, counts only while that slot is worn, needs the same resolve as skill ranks, and is capped by the Taller's upgrades. Equipped by dragging from the inventory onto a hero slot or a hero on the stage; locked during fights.
- **Status effects** (owner 2026-11-08: every Darkest Dungeon status, Tico names) are data in `data/statuses.json`, rules in `scripts/domain/status_effects.gd`: Sangrado (bleed), Envenenado (blight), Atarantado (stun) → Espabilado (stun resist), Salado (debuff), Fichado (mark), Susto (horror), Chiva (buff), Encarrerado (crit buff), Al cuido / Cuidando (guard an ally), Respondón (riposte), Sobado (restoration), Santiguado (aegis), Agazapado (stealth), plus the hero states Al Borde (Death's Door) and Convaleciente (Death's Door recovery). Skills/items use `applies` / `self_applies` ({status, chance, turns, value, mods}), `cure`, `vs_marked_pct`, `guard_ally`; enemies may have `status_resist`. Amarrado (root) blocks every kind of move; it is resisted with Empujones (`movimiento`).
- **Formation** (P1-03a, owner 2026-11-11): each side has positions 1–4 (1 = front, nearest the middle); positions count only the living, and the fallen move to the back. In-game text says **posición** ("rango" is the Casa Comunal skill level). Hero skills need `use_ranks`; enemy-target skills also `target_ranks`. Classes and enemies have preferred `ranks` (docs 03 and 05). Enemy single-target skills need `target_ranks`; they may be used from anywhere unless `use_ranks` says otherwise. The validator requires that every class can hit enemy position 1 from one of its own positions, and that every enemy can hit hero position 1 (or the whole party) from anywhere, so no fight can stall. "Moverse" swaps the acting hero with a neighbour (spends the turn); an enemy with nothing in reach steps toward its preferred positions. The last one standing on a side may use any of its skills from any position (`target_ranks` still apply; owner 2026-11-17, P1-21). Party order in the hub is the starting formation; it carries over between fights, and the hero card has "← Adelante / Atrás →" outside combat. Long-range hero skills (owner 2026-11-19: used from position 3 or 4 and reaching 3 or 4, e.g. Dron Casero) reach every enemy position 1–4. Single-target skills may push/pull (`move_target`, negative = toward the front) or shuffle (`shuffle_target`), resisted with `status_resist.movimiento` (Empujones).
- **Al Borde and crits** (P1-05, owner 2026-11-11): a hero hit while Al Borde rolls to survive (Golpe de gracia %, −8 per earlier roll this expedition, −10/−20 at 100/150 stress, −30 on a Colapso); surviving keeps them Al Borde at 0 PV. A hero's crit relieves 3 stress for the party; enemies crit (5% base, `crit` in data) for ×1.5 damage and +10 stress on the hero hit. The numbers are in `data/balance.json` (`death.*`, `crits.*`, `combat.enemy_base_crit`).
- **Dragging fights** (P5-02b, owner 2026-11-14, DD stall penalty): from round 8 on (round 12 against a boss), every living hero gains 4 stress at the start of the round, 2 more each round after. It keeps parties that out-heal the enemy from stalling. A hero already at 200 stress collapses from it, and a second Colapso in the same fight is a death roll even if the hero was healed back up. The numbers are in `data/balance.json` (`combat.drag_*`).
- **Retreat** (P5-04, owner 2026-11-15, as in Darkest Dungeon): in a fight, "Retirada" works 75% of the time (a failed try spends the turn), costs every living hero 10 stress and takes the party back to the room it came from; the enemies stay. Not from a night ambush. "Abandonar expedición" on the map keeps the colones and items already found, with no objective reward and no resolve XP. The numbers are in `data/balance.json` (`combat.retreat_*`).
- **Men and women** (owner 2026-11-19): every hero has a `sex` ("m" | "f"). Each class lists `names_m` and `names_f` (≥ 15 each, Tico, no name in two places; the validator checks), `class_names` {m, f} and `base_sex` (what its own art shows). Art for the other sex lives at `assets/portraits/<id>_<sex>.png` and `assets/sprites/<id>_<sex>/`; always get paths from `GameState.portrait_path(h)` / `sprite_id(h)`. Recruits skip names already in use.
- **Battle sprites:** a character looks identical in all poses (same outfit and weapon); only the pose changes. The attack pose uses that character's weapon, held in the **right arm**. The party stands on the **right** of the battle stage facing **left**, enemies on the left (owner 2026-11-08), so sprites are generated facing left and enemies are mirrored. Sprites must **look like the character's portrait** (same face, hair, clothes, colors): `tools/sd_sprites.py` feeds the portrait in as an IP-Adapter image prompt, and each `look` in `tools/art_manifest.json` describes what the portrait shows.

## 5. Status vocabulary

| Status | Meaning |
|---|---|
| `todo` | Not started |
| `in-progress (agent, branch, date)` | Claimed; someone is on it or stopped mid-way |
| `review` | Implemented; needs a human playtest or approval |
| `blocked — reason` | Can't continue without a decision or resource |
| `done` | Acceptance criteria met and verified |
| `cut — reason` | Deliberately dropped |

## 6. Repo facts agents keep re-discovering

- Engine: Godot 4.7 (moved from 4.6 on 2026-11-11), GDScript, Forward+. Main scene `scenes/bootstrap/main.tscn`. Autoloads: `GameState`, `SaveService`, `Telemetry`, `TooltipStyler`.
- `GameState` (`scripts/autoload/game_state.gd`) owns all run and campaign state. Save is `user://save.json`, `SAVE_VERSION` in that file. Bump it and add migration in `apply_save_data` when you change the shape, and first add the outgoing version's fixture to `tests/fixtures/` (`save_v<N>.json`, made with `tools/dump_save.gd` from that version's commit; see `tests/fixtures/README.md`). `tests/test_save_migration.gd` (P3-08) loads every fixture with today's code. `SaveService` (P1-19) is off while a `-s` script runs (tests, sim and screenshot tools start from a fresh catalog party and never touch the owner's save), writes through a temp file + `save.json.bak`, and copies an unreadable save aside (`save.broken-<time>.json`) before loading the `.bak`.
- Language: in-game text is **Spanish (Costa Rican)**. Code, comments, and docs are English.
- Telemetry (P5-01): the `Telemetry` autoload appends JSON lines to `user://telemetry.jsonl` (mission_end, stress_spike, week, session); off in `-s` runs. `tools/playtest_campaign.gd -- --telemetry <path>` writes one from bot campaigns; `python3 tools/telemetry_report.py [path]` summarises it.
- Tone guardrails: [docs/08-content-standards-satire.md](docs/08-content-standards-satire.md). Read it before writing any flavor text.
- Tooltips: just set `tooltip_text` ("Title\nbody" or "Title — body"); the `TooltipStyler` autoload draws it as the shared card (`scripts/ui/tooltip_card.gd`). Custom tooltips call `TooltipCard.clear_frame(self)` and return a card from `_make_custom_tooltip`.
- UI style (P4-15, owner 2026-11-17: every menu in the item-card style):
  - `scripts/ui/ui_theme.gd` is the game-wide theme (buttons, dialogs, dropdowns, check boxes, scroll bars); `TooltipStyler` sets it on the root window. Don't restyle those per screen.
  - Build menus and cards from `tooltip_card.gd` parts: `new_card`, `title_label`, `chip`, `picture`, `section`, `rule`, `bullet_list` (bad lines turn red via `is_bad_line`).
  - Hero cards: `scripts/ui/hero_card.gd`.
  - A button with a card on hover: `scripts/ui/card_button.gd` (set `card` to a Callable).
  - Hub dialogs: `_card_dialog` + `_popup_card` in `hacienda_hub.gd`.
  - The hub is a town view (P4-17): building pictures and positions in `data/town.json`, one `scripts/hacienda/town_building.gd` each. A click calls `open_building(id)`, which shows the page `Building/VBox/Pages/<id>` in `hacienda_hub.tscn`. New town art: an entry in `tools/art_manifest.json` with `"cutout": true`, then `tools/sd_local.py`, then `tools/sd_cutout.py`; then repaint the whole town with `tools/town_paint.py` (P4-19: layout → img2img + ControlNet canny → `town_painted.png` + one crop per building in `assets/town/painted/`). Moving a building in `data/town.json` means repainting. Keep SD prompts under CLIP's 77 tokens or the style words get cut.
- Regions (P6-01): `data/regions.json` lists every region in campaign order with its `unlock` (and `wip` while being built; debug builds only). A region file is generated (`generator` with pools, `boss_enemy_id`, `curios`, `traps`, labels) and names its `boss_name`; optional `background` / `combat_background`. Clears are `GameState.regions_cleared` (recorded in `complete_mission`); rules in `scripts/domain/region_progress.gd`. Add a new region's row to `regions.json` or the validator fails.
- Sounds (P4-04a): `Sfx.play("id")` (autoload `scripts/autoload/sfx.gd`); ids, files, bus and volume in `data/sfx.json`, built by `tools/import_sfx.py` from CC0 OpenGameArt packs (credits in `assets/audio/CREDITS.md`; every sound file has a `.metadata.json`). Every button clicks by itself (meta `no_ui_sfx` opts out); hub actions go through `_act(sound, call)` in `hacienda_hub.gd`; the combat controller uses `_sfx(id)`, silent in `instant` sims. Buses: SFX, UI, Music, Voice; the speaker button (`scripts/ui/volume_button.gd`) keeps the volume in `user://settings.cfg`. The validator checks files, metadata and every id the code plays.
- Art: follow [.cursor/rules/stable-diffusion-assets.mdc](.cursor/rules/stable-diffusion-assets.mdc). Never call SD from game code. Every PNG needs a `.metadata.json`.
- Balance experiments: `godot --headless --path . -s tools/sim_combat.gd -- --runs 10000 [--chain 3] [--set path=value] [--party id,id,id,id] [--level N --ranks R --gear] [--log-long N]` plays the real combat controller headless (doc 10 "Combat sim"). Rerun it after changing combat numbers. `tools/playtest_campaign.gd -- [--campaigns 3] [--weeks 8] [--route full|direct] [--set path=value] [--party id,id,id,id]` plays whole campaigns (hub + expeditions) through the real expedition screen with a careful-player bot that also spends like a player: provisions, EBAIS, Iglesia, skill ranks, equipment (doc 09 §5–6). The balance pass (P5-02a–f) compares every change with the baselines in `docs/playtests/`. Both share the hero policy in `tools/sim_policy.gd`.
- The Godot path in `.cursor/rules/godot-runtime.mdc` is the owner's Windows machine. Cloud containers usually have no Godot.
